# Strategy & Organizational Notes

Context from meetings with the Morpheus Asia dev team and global coordinator David
Johnstone, ahead of and around the Jul 30–31 Web3 event. Organizational/strategic —
kept separate from AUDIT.md's technical findings.

**Last updated:** 2026-08-01

## Onboarding (validates this project's findings independently)

- General-audience description of Morpheus is considered weak for laymen — same gap
  this project's guides (windows-setup-guide.md, the beginner Desktop App walkthrough)
  were built to close.
- A dedicated **onboarding.org** site is planned, covering both API Gateway and Native
  paths, with **video breakdowns going beyond setup** into actual use and
  troubleshooting — same structure this project independently arrived at
  (installer / free-local / developer paths, screenshot-driven).
- A **YouTube channel** is planned to host these videos.
- The developer route/onboarding funnel is acknowledged as needing improvement.
- **The Asia team independently flagged `mor-cli` errors and a chat-history/context
  error** — these are the same issues filed by this project as
  [#792](https://github.com/MorpheusAIs/Morpheus-Lumerin-Node/issues/792) (mor-cli,
  Windows cookie bug + 3 follow-ups) and
  [#794](https://github.com/MorpheusAIs/Morpheus-Lumerin-Node/issues/794) (context not
  retained by default). Real, independent confirmation from a second party.

## Communication platform

- Community is consolidating onto **Slack** (moving away from prior scattered
  channels); Slack workflows are now largely automated.

## Planned AI support tiering

- Common/simple questions to be handled automatically by an AI support layer.
- Complex/technical questions escalate to core developers.
- The AI's knowledge base is expected to expand and improve as more interactions
  accumulate over time.

## Global adoption — Asia-run app.mor.org instance

- Proposal (Rene): run a **regional app.mor.org instance for Asia**, supporting local
  payment gateways, converting fiat payment into token access ("time to tokens") with
  a business margin.
- David: flagged a real risk in the current mechanism — using **MOR DIEM** effectively
  gifts tokens to Kyle's side, who then deposits them, which is risky exposure on his
  end. **Staking instead of gifting is lower-risk.** Currently requires a **hot
  wallet**; a **cold-wallet-compatible update is coming soon**, which would reduce
  this risk further.
- Framed by David as **"a bootstrapping mechanism"** — i.e., an interim/transitional
  approach, not necessarily the permanent design.

## Contribution measurement is an acknowledged, unsolved problem

- David: contributions are hard to measure fairly because many are one-off, low
  value, or outright **false bug reports generated by AI agents**, alongside
  duplicates of already-known issues.
- Relevant to this project's own contribution trail (6 issues, 1 merged PR) — all
  independently reproduced with clear repro steps, which is exactly the kind of
  signal that should be easy to distinguish from noise, but the fact that the team
  finds this hard in general is worth keeping in mind for how future contributions
  are packaged and presented.

## Morpheus Doctor — future direction

- Demoed `morpheus-doctor` to David; well received.
- Discussed evolving it beyond its current scope (session/inference automation +
  preflight) into an actual **diagnosis-and-auto-fix tool** — living up to the
  "Doctor" name more literally: detect a problem, explain it, and where possible,
  fix it automatically (e.g. stale cookie, wrong chain config, corrupted local data —
  several of which this project already manually diagnosed and fixed by hand over
  the course of this internship).
